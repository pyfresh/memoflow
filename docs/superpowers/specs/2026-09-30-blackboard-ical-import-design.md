# Blackboard iCalendar 导入设计

> 状态：已废弃。产品已收敛为登录 Blackboard 后从课程日历页面导入；保留此文件作为历史设计记录，不代表当前版本提供 iCalendar 入口。

## 目标

MemoFlow 支持从 Blackboard 生成的私有 iCalendar Feed 导入当前勾选的全部日历内容，包括 Institution、Personal 和课程日历。用户完成一次链接粘贴和读取后，可以在预览页确认批量导入。

## 用户流程

1. 用户在 Blackboard Calendar 点击 `Get External Calendar Link`，复制私有 `.ics` 地址。
2. 用户在 MemoFlow 的 Blackboard 导入窗口中选择“通过 iCal 链接导入”，粘贴地址并点击“读取 iCal”。
3. MemoFlow 校验链接来源，读取并解析日历内容，显示读取中、分析中、成功、空结果或失败状态。
4. 预览页显示全部候选事项和课程时段，默认全选；用户可以取消个别事项后确认导入。
5. 确认后写入备忘录、提醒、Blackboard 映射和周课表数据，使用事件 UID 和已有映射去重。

当前页面读取方式继续保留，作为 iCal 不可用或用户没有链接时的备用流程。

## 数据流与边界

MemoFlow 前端把链接发送给 Tauri 命令。Rust 层只接受 `https://bb.cuhk.edu.cn/` 下的地址，并限制响应大小、响应状态和内容类型。桌面版使用系统 HTTPS 客户端执行带超时的请求；Blackboard 的私有 token 已包含在用户复制的 Feed 地址中，不把登录 Cookie 或地址写入日志。解析后的结构化数据只在当前导入流程中使用，不把原始 Feed 内容写入日志。

链接默认只用于当前导入，不保存到代码、仓库或远程服务。界面明确提示该地址带有私密令牌，用户不应分享。

## iCalendar 映射

每个 `VEVENT` 映射为一个导入候选：

- `UID`：外部唯一标识，用于重复导入和更新。
- `SUMMARY`：事项标题；缺失时跳过并记录解析错误。
- `DUE`、`DTEND`、`DTSTART`：按优先级选择提醒时间，并统一为香港时区的本地 ISO 格式。
- `DESCRIPTION`：备忘录正文，保留纯文本并清理 iCalendar 转义。
- `URL`：Blackboard 项目链接。
- `CATEGORIES`、日历名称或 Blackboard 扩展字段：课程名称和事项分类。
- `RRULE`：只映射现有支持的每日、每周、每月重复规则；其他规则作为一次性事件导入并在预览中提示。

标题和分类包含 `assignment`、`homework`、`project`、`exam` 等关键词时，映射到对应类型；Institution、Personal 等没有课程信息的事件标记为普通事件。

具有明确星期、开始时间、结束时间和课程信息的重复课程事件可以生成周课表候选。无法可靠识别为课程时段的事件只进入备忘录和提醒，不根据截止时间猜测课程。

## 错误处理

错误必须显示在当前导入窗口，并区分以下情况：

- 链接为空或来源不是 Blackboard：提示重新粘贴官方 iCal 地址。
- 网络失败、登录失效或 HTTP 非成功状态：提示检查 Blackboard 登录和链接是否过期。
- 内容不是 iCalendar 或解析失败：提示重新生成链接。
- Feed 没有事件：提示当前勾选日历没有可导入内容。
- 单个事件字段缺失：跳过该事件，在预览状态中显示跳过数量。

读取期间按钮禁用，状态变化后才恢复操作，避免用户无法判断请求是否生效。

## 测试与验收

- 使用包含作业、考试、Personal 事件、重复课程和转义文本的 `.ics` 固定样例测试解析。
- 验证时区转换、RRULE 映射、UID 去重、更新已有事项和空 Feed 行为。
- 验证非法主机、超大响应、非 iCalendar 内容和过期链接的错误状态。
- 运行前端类型检查、完整 Vitest 测试、Rust 测试和 Windows Tauri 生产构建。
- 手动验收：粘贴 Blackboard 链接，预览全部勾选日历，确认后在备忘录、提醒和周课表中看到对应数据。
