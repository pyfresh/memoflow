# 日历事项详情页操作按钮设计

## 背景

当前点击月历事项后会打开已有的事项编辑详情页。用户需要在这个详情页直接完成事项或删除事项，避免先返回列表再操作。

## 已确认的交互设计

- 采用标题栏操作布局（B 方案）。
- 详情标题右侧依次放置“完成”“删除”和关闭按钮。
- “完成”使用绿色，表示正向状态变更。
- “删除”使用红色系浅色按钮，表示破坏性操作，同时保留清晰的文字标签。
- 关闭按钮保持中性颜色，不与业务操作混淆。
- 详情正文继续保留现有内容编辑、提醒信息和 Blackboard 作业跳转按钮。

## 行为与数据流

1. 月历事项触发 `select` 事件后，沿用现有 `App.svelte` 选中逻辑打开 `ReminderEditor`。
2. `ReminderEditor` 在有 `initial.id` 时显示完成和删除按钮；新建事项不显示这两个按钮。
3. 点击“完成”向上派发带事项 ID 的事件，由 `App.svelte` 调用现有 `repository.setReminderStatus(id, 'completed')`，刷新快照并持久化。
4. 点击“删除”向上派发带事项 ID 的事件。
   - 有关联备忘录时调用 `repository.deleteMemo(memoId)`，同时移除关联提醒和外部映射。
   - 只有独立提醒时调用 `repository.deleteReminder(reminderId)`。
   - 删除后关闭详情页、刷新月历和最近事项，并持久化到桌面驱动。
5. 完成和删除均阻止表单提交，避免误触发保存。

## 错误与反馈

- 完成成功后关闭详情页，月历事项状态立即更新。
- 删除成功后关闭详情页，事项从月历和列表中消失。
- 若数据层找不到目标 ID，操作保持幂等，页面仍刷新当前快照。
- 删除按钮使用明确的危险色，但不增加额外确认弹窗，以保持轻量和高响应；用户可通过关闭按钮取消操作。

## Blackboard 作业提醒规则

- `itemType === 'assignment'` 或 `itemType === 'project'` 的 Blackboard 作业/项目继续以截止时间显示在月历上，但通知触发时间设为截止时间前一天的同一时刻。
- 普通备忘录、独立提醒以及其他 Blackboard 事项仍在各自的截止时间触发通知。
- 提醒时间作为事项数据的一部分持久化；作业截止时间被同步更新时，提前一天的通知时间同步重算。
- 重复作业沿用每次 occurrence 的截止时间，并为下一次 occurrence 重算提前一天的通知时间。
- 若作业截止时间距离当前不足一天，导入后立即进入可通知窗口，由调度器在下一次 tick 发送。

## 测试范围

- 组件测试：编辑已有事项时显示完成、删除按钮；新建事项时不显示；事件携带正确 ID。
- 组件测试：按钮点击不会提交保存表单。
- 集成测试：月历事项点击后打开详情并完成/删除对应提醒或备忘录。
- 回归测试：现有保存、关闭、Blackboard 跳转和独立提醒流程继续通过。
