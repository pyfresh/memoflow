# PushPlus 微信提醒设计

## 目标

为 MemoFlow 增加个人微信提醒能力，使用 PushPlus 微信服务号渠道发送提醒，同时保留 Windows 原生通知作为本机兜底。首版保持轻量，不接入微信客户端自动化，也不引入 ClawBot 运行时。

## 用户体验

- 设置页提供 PushPlus Token 输入框、启用开关和“发送测试提醒”按钮。
- 用户保存 Token 后，可以立即发送一条测试消息确认配置是否有效。
- 到达提醒时间时，消息包含事项标题、截止时间；Blackboard 事项额外包含课程代码和作业类型，正文不默认发送。
- PushPlus 发送成功后仍发送 Windows 原生通知，保证本机有即时反馈。
- PushPlus 发送失败时保留本机通知，并在应用内显示可读错误；失败不会把提醒标记为已发送，下一次调度会重试。

## 架构

通知发送器拆成渠道适配器：

- `native`：复用现有 Tauri notification 插件。
- `pushplus`：由 Tauri Rust 命令向 PushPlus HTTPS API 发起请求，避免 WebView 跨域和 Token 暴露在前端请求中。
- 调度器负责读取到期提醒、按启用渠道发送、记录结果；渠道实现不直接修改提醒数据。

PushPlus 请求使用微信服务号渠道参数 `channel=wechat`，模板使用纯文本，内容只发送必要的标题、时间和课程标签。Token 作为本地敏感配置保存，不进入导出文件、日志或版本库。

## 数据和失败处理

- 在现有桌面持久化层增加通知设置和每个渠道的最近发送状态。
- 一条提醒的“已发送”状态只有在启用的外部渠道全部成功，或用户明确关闭外部渠道后才更新。
- HTTP 错误、PushPlus 业务错误码、超时和网络断开都转换为用户可读的失败原因。
- 不在日志中记录完整 Token；测试按钮和正式提醒使用同一套发送函数。
- 首版不承诺应用完全退出时仍能发送。后台行为依赖应用托盘常驻/开机启动，后续单独实现。

## 安全和限制

- Token 仅允许通过设置页输入和清除。
- 发送正文不包含备忘录全文，降低第三方服务暴露的信息量。
- PushPlus 的实名认证、每日额度、频率限制和相同内容限制由服务端执行，应用在返回错误时明确提示。

## 测试范围

- 测试请求构造：渠道、标题、正文和 Token 传递正确，日志脱敏。
- 测试成功、HTTP 失败、业务错误、超时和重试行为。
- 测试设置保存、清除、测试发送和应用重启后的恢复。
- 测试现有本地通知、Blackboard 导入、课程表和提醒调度不回归。
- 使用本地 HTTP mock 验证 PushPlus，不在测试中使用真实 Token。
