# 通知设置状态与侧栏清理

## 目标

保存通知设置后，界面立即反映新状态并给出明确反馈；移除不再属于当前产品流程的示例数据和导出入口。

## 设计

- `NotificationSettings` 保存成功后显示“通知设置已保存”，同时继续通过 `onSave` 把规范化后的设置交给页面。
- `App` 在保存回调中先更新内存中的 `notificationSettings`，再写入 repository 并刷新持久化状态；重新打开弹窗时使用最新值。
- `Sidebar` 只保留 Blackboard 导入和通知设置入口，移除加载示例数据、导出 Markdown、导出纯文本三个操作及其事件类型。
- `App` 删除示例数据提示、种子数据处理和两个导出函数及相关导入，避免保留不可达逻辑。

## 验证

- 通知设置组件测试保存后检查成功状态文本。
- 仪表盘测试检查旧侧栏按钮不存在，并保留 Blackboard 导入和搜索入口。
- 运行 `npm run check`、`npm run test:run` 和生产构建。
